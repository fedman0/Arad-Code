## FLOW VERIFICATION PROTOCOL — run for every candidate before submitting

For each grep match:

**a.** `get_code_snippet("containing_function_or_class")` — read the full enclosing function.

**b.** Identify variable `D` passed to the deserializer / XML parser.

**c.** Trace D's origin:
- Internal data only (generated by the app itself, never from network) → **SKIP**
- User-supplied: HTTP body, file upload, multipart form, Redis/Kafka/DB field populated by users, network socket → **CONTINUE**
- Unclear → `trace_path("function_name", mode="data_flow", direction="inbound")` upstream; if still unclear, **submit with confidence=5** (uncertain is not safe)

**d.** Check for safeguards:
- Deserialization: `ValidatingObjectInputStream` with allowlist (Java), `yaml.safe_load` instead of `yaml.load` (Python), HMAC signature verified before deserializing → **SKIP**
- XXE: `setFeature("…disallow-doctype-decl", true)` / `LIBXML_NOENT` absent / `defusedxml` used → **SKIP**
- Raw deserializer on network data with no integrity check → **SUBMIT**

**Submit only when confirmed**: name function, variable, source type, and missing guard (e.g. `request.body bytes passed to ObjectInputStream in parsePayload() with no class allowlist`).

## Step 1 — Unsafe deserialization: Python

**pickle / marshal / shelve:**
```
grep(pattern="(c|_)?[Pp]ickle\.(loads?|Unpickler)\s*\(|marshal\.loads?\s*\(|shelve\.open\s*\(|read_pickle\s*\(|allow_pickle\s*=\s*True", max_matches=20)
```

**YAML unsafe loaders:**
```
grep(pattern="yaml\.(load|load_all)\s*\(.*Loader\s*=\s*(yaml\.)?(FullLoader|UnsafeLoader|Loader|CLoader|CFullLoader|CUnsafeLoader)\b|yaml\.(load|load_all)\s*\([^,]*\)\s*($|[;#)\]}.\[])|yaml\.(unsafe_load|unsafe_load_all|full_load|full_load_all)\s*\(|YAML\(\s*typ\s*=\s*['\"]unsafe['\"]", max_matches=20)
```

**Other unsafe deserializers:**
```
grep(pattern="jsonpickle\.decode\s*\(|dill\.loads?\s*\(|cloudpickle\.loads?\s*\(|torch\.load\s*\(|joblib\.load\s*\(", max_matches=20)
```

For each match: does the data source derive from HTTP request body, file upload, Redis, database field, or any network-received value? Safe: `pickle.loads` on data you generated yourself and signed; `torch.load(..., weights_only=True)` (the default since PyTorch 2.6).

→ Submit: violated_invariant="Untrusted data passed to [pickle/yaml.load/dill]; arbitrary code execution on deserialization", severity=10, confidence=8, exposure="internet", cwe="CWE-502"

## Step 2 — Unsafe deserialization: Java

**ObjectInputStream (Java native):**
```
grep(pattern="new ObjectInputStream\s*\(|ObjectInputStream\s*\(\s*\w+\s*\)|\.readObject\s*\(\s*\)", max_matches=20)
```

**Jackson default typing / Fastjson autoType (polymorphic deserialization):**
```
grep(pattern="enableDefaultTyping\s*\(|activateDefaultTyping(AsProperty)?\s*\(|JsonTypeInfo\.Id\.(CLASS|MINIMAL_CLASS)|LaissezFaireSubTypeValidator|setAutoTypeSupport\s*\(\s*true|Feature\.SupportAutoType", max_matches=20)
```
`activateDefaultTyping` is safe only with an allowlisting `PolymorphicTypeValidator` (not `LaissezFaireSubTypeValidator.instance`).

**XStream / XMLDecoder / SnakeYAML:**
```
grep(pattern="new XStream\s*\(|xstream\.fromXML\s*\(|new XMLDecoder\s*\(|new Yaml\s*\(\s*(new Constructor\s*\([^)]*\))?\s*\)", max_matches=20)
```
SnakeYAML `new Yaml()` / `new Yaml(new Constructor(...))` followed by `.load(` on untrusted input is RCE on SnakeYAML < 2.0; `new Yaml(new SafeConstructor(...))` is safe.

For each `new ObjectInputStream`: trace the constructor argument — is it from `request.getInputStream()`, a socket, or a user-uploaded file? SafeDeserialization wrappers like `ValidatingObjectInputStream` with allowed classes are safe.

→ Submit: violated_invariant="Java ObjectInputStream/XStream deserializes attacker-controlled bytes; known gadget chains lead to RCE", severity=10, confidence=8, exposure="internet", cwe="CWE-502"

## Step 7 — XXE: Java (XML parsers not hardened)

**XMLInputFactory external entities enabled:**
```
grep(pattern="setProperty\s*\(.*(IS_SUPPORTING_EXTERNAL_ENTITIES|isSupportingExternalEntities).*(?i:true)", max_matches=15)
```

**DocumentBuilderFactory without DTD disabled:**
```
grep(pattern="DocumentBuilderFactory\.new(Default)?Instance\s*\(", max_matches=20)
```

For each `DocumentBuilderFactory.newInstance()`: verify `setFeature("http://apache.org/xml/features/disallow-doctype-decl", true)` is called on the factory, or both `external-general-entities` and `external-parameter-entities` are set to `false`, or `XMLConstants.ACCESS_EXTERNAL_DTD` is set to `""`. If none of these, XXE is live.

**SAXParserFactory / TransformerFactory / StAX / dom4j / JDOM:**
```
grep(pattern="SAXParserFactory\.new(Default)?Instance\s*\(|TransformerFactory\.newInstance\s*\(|XMLInputFactory\.new(Default)?(Factory|Instance)\s*\(|SchemaFactory\.newInstance\s*\(|XMLReaderFactory\.createXMLReader\s*\(|new SAXReader\s*\(|new SAXBuilder\s*\(", max_matches=15)
```
Same check; for `XMLInputFactory` the hardening is `SUPPORT_DTD` = false or `IS_SUPPORTING_EXTERNAL_ENTITIES` = false; for `TransformerFactory` / `SchemaFactory` it is `ACCESS_EXTERNAL_DTD` and `ACCESS_EXTERNAL_STYLESHEET` / `ACCESS_EXTERNAL_SCHEMA` set to `""`.

→ Submit: violated_invariant="XML parser [factory] instantiated without disabling external entity processing; XXE reads arbitrary files / SSRF", severity=9, confidence=7, exposure="internet", cwe="CWE-611"

## Step 9 — XXE: Python (lxml / sax with external entities enabled)

```
grep(pattern="resolve_entities\s*=\s*True|no_network\s*=\s*False|feature_external_(ges|pes)\s*,\s*(True|1)\b", max_matches=20)
```

```
grep(pattern="from lxml import etree|import lxml\.etree|lxml\.etree\.(fromstring|parse|XML)\s*\(", max_matches=20)
```

For the first grep: an lxml `XMLParser(resolve_entities=True)` or a sax / pulldom parser with `feature_external_ges` enabled that parses user XML → **SUBMIT**. For lxml imports: lxml < 5.0 resolves external entities by default (5.0 changed the `resolve_entities` default to `'internal'`) — check the pinned lxml version (requirements*.txt / pyproject.toml / poetry.lock) and whether user XML reaches `etree.fromstring/parse/XML` without `XMLParser(resolve_entities=False)`.

Python stdlib parsers (`xml.etree.ElementTree`, `xml.dom.minidom`, `xml.sax`, `pyexpat`) do NOT resolve external entities by default → **SKIP** for XXE (entity-expansion DoS is a separate, lower-severity issue that `defusedxml` addresses).

Safe signal: `defusedxml` used, or `etree.XMLParser(resolve_entities=False)`.

→ Submit: violated_invariant="Python XML parser configured to resolve external entities (lxml resolve_entities / lxml<5 default / sax feature_external_ges) on user XML; XXE reads local files", severity=9, confidence=7, exposure="internet", cwe="CWE-611"

**Resolver or DTD processing explicitly enabled:**
```
grep(pattern="XmlResolver\s*=\s*new XmlUrlResolver|DtdProcessing\s*=\s*DtdProcessing\.Parse|ProhibitDtd\s*=\s*false", max_matches=20)
```

**Legacy-framework defaults:**
```
grep(pattern="new XmlDocument\s*\(\s*\)|new XmlTextReader\s*\(|new XPathDocument\s*\(", max_matches=20)
```

For the first grep: the setting applies to a parser that reads user XML → **SUBMIT**. For the second: `XmlDocument`, `XmlTextReader` and `XPathDocument` do not resolve external entities by default on .NET Framework 4.5.2+ and .NET Core / .NET 5+ (and `XmlReaderSettings` defaults to `DtdProcessing.Prohibit`) → **SKIP** unless the project targets an older framework (`<TargetFrameworkVersion>` below v4.5.2 in *.csproj, or `targetFramework` in web.config) and no `XmlResolver = null` is set.

## Step 14 — Unsafe deserialization: Go (encoding/gob, json.Unmarshal to interface{})

```
grep(pattern="gob\.NewDecoder\s*\(", max_matches=15)
```

```
grep(pattern="json\.Unmarshal\s*\([^,]+,\s*&\w*[Ii]nterface\w*\s*\)|json\.Unmarshal\s*\([^,]+,\s*&interface", max_matches=15)
```

```
grep(pattern="yaml\.Unmarshal\s*\([^,]+,\s*&\w+\)|xml\.Unmarshal\s*\([^,]+,\s*&\w+\)", max_matches=20)
```

For each: is the source `r.Body`, a user-uploaded file, or a Redis/Kafka message with attacker-controlled content? Go's standard decoders do not instantiate code-bearing types, so there is no RCE gadget chain (gob only decodes into types registered with `gob.Register`). Realistic impact: denial of service from crafted input (e.g. CVE-2022-30635 gob stack exhaustion, fixed in Go 1.17.12 / 1.18.4) and type confusion when untyped `interface{}` values are type-asserted without checks.

→ Submit: violated_invariant="Go gob/encoding decoder consumes untrusted stream; crafted input causes resource exhaustion or unexpected types", severity=5, confidence=6, exposure="internet", cwe="CWE-502"
